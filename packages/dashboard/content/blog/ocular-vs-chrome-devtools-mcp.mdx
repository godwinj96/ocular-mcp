## One line between them

[chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp) and Ocular both give an
AI coding agent a way to see a web page. They split on one question: whether that page is one your
own browser can already open.

chrome-devtools-mcp drives your local Chrome. Ocular renders the page and hands back what it saw,
including pages your local Chrome was never going to reach.

That is the comparison. Everything below is detail.

## What Ocular does differently

**One connection covers both sides of the line.** Your dev server on localhost and pages out on the
open web come through the same MCP server, with the same four tools. There is no second tool to
install for the half your local browser can’t open, and nothing to decide at call time about which
one to reach for. Base tier clears most of the open web. Most, not all.

**What comes back is the render, with structure attached.** A screenshot, plus the element tree
behind it, annotated with what is in view, what sits below the fold, and where each thing is. Not a
DOM dump for the agent to infer a layout from. The thing that actually painted, and the structure
underneath it, in one reply.

**Motion arrives as stills it can actually read.** Claude accepts no video, and an animated GIF is
read as its first frame only. An animation or a scroll effect comes back as a tiled contact sheet,
which costs one image and shows the whole sequence.

**It never touches the page.** There is no click, type or navigate anywhere in the tool surface,
which means there is nothing to trigger by accident and nothing to switch off. On localhost it is
unmetered, because that is your own machine doing the work.

|                  | chrome-devtools-mcp             | Ocular                   |
| ---------------- | ------------------------------- | ------------------------ |
| Coverage         | Local Chrome only               | Localhost + the open web |
| Acts on the page | Yes: clicks, types, fills forms | No, by design            |
| Tools            | ~58                             | 4, all read-only         |
| Made by          | Google                          | One developer            |
| Price            | Free                            | From $2.50/mo            |

## Where chrome-devtools-mcp is the better tool

It is Google’s own, it is free, and it is not a niche project: 51.6k GitHub stars and 1.43 million
npm installs a week. If your agent has touched a browser recently, there is a good chance this is
what it reached for.

It also does something Ocular structurally cannot. Ten of its tools handle input alone, plus
navigation, waiting, Lighthouse, traces, and the console and network panels. It can run an
interaction end to end. If the job is “click through this checkout flow and tell me what broke,”
that is the tool, and Ocular was never trying to be it.

Read-only isn’t fifty-four tools short. It is a different job: eyes on something rather than hands
on it. A driving seat left open on a page you were never going to operate is not a feature you
asked for, and a tool that can act on a live page can also modify one. That is a property of what a
driving seat is for, not a claim about which tool is safer to point at any given page. Whatever
either one renders still lands in your agent’s context.

## The boundary, in their own words

chrome-devtools-mcp’s documentation is direct about its shape. It drives **your own local Chrome**,
“designed to run on the same machine as the browser.” Remote Chrome appears there as a possible
future direction, not a feature. That isn’t a limitation the project is hiding. It is what a
debugging tool for the browser you already have open is supposed to be.

It does mean the boundary is real. Point it at a page that isn’t running on your machine and you are
back to describing that page to your agent instead of showing it.

## Setup, and what it costs to keep running

Both are a few lines in an MCP client config with nothing else to install. chrome-devtools-mcp
launches via `npx`. Ocular’s local worker does the same, then asks for a one-time sign-in, the way
any CLI tool authenticates once and remembers.

chrome-devtools-mcp is free, with no ceiling to run into. Ocular is $2.50 a month: unmetered on
localhost, and 40 renders a day on the open web, because that half runs through infrastructure that
isn’t free.

## Where this earns its keep

Three ordinary moments, all of which end the same way today. Your agent asks you to go look, or it
works from your description of what it can’t see.

**A competitor built something and you want to know how.** Their page runs on their machine, not
yours. Nothing local opens it for your agent.

**A teammate drops a staging link in Slack.** It sits behind a URL your local Chrome profile has
never seen.

**Your agent needs the current documentation**, not the version that was in its training data the
day it shipped.

None of these are exotic. They are the ordinary shape of a working week, and every one of them is a
point where a localhost-bound tool runs out of road.

## Which one you want

If your agent only ever looks at pages running on your own machine, and you want it driving them,
chrome-devtools-mcp is the right answer and it is free.

Ocular is for the other half of the job: the page your agent can’t drive to, and your dev server,
from one connection. Four tools that only look, $2.50 a month, unmetered on localhost.
